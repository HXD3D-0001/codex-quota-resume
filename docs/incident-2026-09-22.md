# 项目开发日志

## 2026-09-22：重置后没有续跑

用户报告：额度恢复后，本任务没有自动继续。

核实：后台在运行，额度响应已恢复，持久化发送记录为空。旧实现用两层 `idle` 条件筛选任务（列表与详情）；限额失败可能处于 `systemError`，因此尚未进入发送逻辑便被排除。首次测试只构造了 `idle + failed`，遗漏了桌面错误状态。

修复：不根据列表徽标过滤任务；读取最新一轮，接受非活动的 `idle`、`systemError` 和 `notLoaded`，但必须明确为安装后的限额失败，或有用户显式待继续标记。活动任务和等待批准/输入标记仍拒绝。把筛选结果写入本地 inspections，便于区分未匹配、已发送、读取失败。

验证：新增错误状态回归测试，修复前失败、修复后通过；已用实际本地管道向本任务发送并成功收到标注自测的继续消息。未人为耗尽账户，下一次自然重置的全流程仍需实际观察。

UI：360×38 逻辑像素、Qt 高 DPI 绘制、原生 Acrylic 背景、完全点击穿透且不抢焦点。控制移到系统托盘。额度仍由独立后台自动查询，倒计时每秒更新。

参考：[Windows 点击穿透示例](https://github.com/cappuccino8080/CrossHair-Overlay)、[py-window-styles](https://github.com/Akascape/py-window-styles)、[Qt 输入透明窗口](https://doc.qt.io/qt-6/qt.html)、[Windows Desktop Acrylic](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwm_systembackdrop_type)。本次没有复制第三方实现。

## 2026-10-30：升级套餐后的单周额度兼容

- 现象：用户报告额度恢复后未自动续跑。现场后台正常，但返回的 `codex` 快照仅有 `primary.windowDurationMins=10080`，`secondary=null`，且 `ordinaryUsageAllowed=true`；旧判断硬性要求两个窗口，因此拒绝恢复。
- 决策：兼容该明确的单周响应；所有恢复均要求服务端明确允许普通使用，保留额度未满、数据新鲜、原任务最新轮次与防重发检查。五小时数据未返回时显示“未提供”，不推断无限额度。当前已在执行的任务不补发。
- 验证：先确认旧版回归失败，修复后 135 项 Python 测试和 3 项隔离桥接测试全部通过，独立审查无遗留问题。实机新后台已识别单周响应并判定额度可用，诊断正常，原发送记录和暂存提示词保留。完整单周恢复通过模拟监测循环验证，未消耗重置卡，也未向正在运行的真实任务补发测试消息。
- 依据：[官方协议的服务端使用许可字段](https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/account.rs)、[相同单周响应的公开问题](https://github.com/openai/codex/issues/32707)。本文件作为唯一开发日志继续维护。
