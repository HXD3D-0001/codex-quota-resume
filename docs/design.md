# Codex 限额恢复助手

项目：codex-quota-resume。目标：修复旧悬浮条仅读取会话日志导致重置后显示陈旧的问题，并在真实额度恢复后继续因限额失败的原任务。

已确认范围：用户授权独立 GitHub 仓库；自动恢复因限额中断的任务，其他任务只有明确标记待继续后才可恢复。每五轮对话同步项目，提交排除本地状态与凭据。

## 实现约定

- Windows、Python 3.11+、Node.js 18+；监测核心为标准库，UI 使用独立目录中的 PySide6 Essentials。360×38 逻辑像素，原生 Acrylic、高 DPI 清晰文字、完全鼠标穿透，控制放到系统托盘。
- 本地守护程序独立于模型运行；通过已安装 Codex app tools 的本地管道协议读取实时额度、任务状态、发送后续消息。此桥接接口来自本机捆绑插件，属于版本相关接口；失效时停止续跑并显示连接错误，不退回盲目 CLI resume。
- 常规 30 秒查询，距重置 30 秒内最多 5 秒间隔，准确调度到重置时间；重置后额度仍阻塞时每 5 秒重查。只有新鲜查询证实所有适用额度可用才续跑。周额度仍耗尽、数据缺失、断网均不放行。
- 最新一轮必须明确失败且错误为 usage limit；不能仅凭 idle、未归档或文本提到额度判定。正在工作、等待输入、手动中断、已完成任务不自动恢复。
- 手动待继续标记绑定最新轮次；后来有新轮次则标记失效。每次发送前重查任务和额度，串行发送。
- SQLite 持久化每个任务/失败轮次的发送记录。发送前先记录 dispatching；请求结果未知时不自动重发，提示人工检查。成功记录 sent。程序单实例。
- 新安装时只监测安装后的限额失败；之前的失败通过手动标记显式纳入，避免重启已被替代的旧项目。
- 保留原任务模型、思考强度和权限设置；只发继续原任务的提示，不传覆盖参数。
- 额度缓存仅供展示；过期明显标记 stale，不把时间经过当作额度恢复。不保存账户 ID、凭据或对话正文。
- Codex 必须运行、电脑必须清醒；恢复运行后立即重新核查。
